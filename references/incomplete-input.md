# 输入不完整时的处理规范

截图被切、长图分栏、真题节选——学习者往往意识不到自己拿到的是半句。这份文件解决三件事：**怎么发现缺口**、**发现后怎么讲**、**缺口怎么被补上**。

核心判断：缺口不是"讲不讲"的问题，是"**必须让学习者当场看见**"的问题。他不看见，就会以为是自己的语法不行。

---

## 一、四种缺口来源（先分清，处理方式不同）

| 来源 | 特征 | 能否补 | 处理 |
|---|---|---|---|
| **图片边缘切断** | 句子止于图片最上/最下一行，缺字处常伴随半截字形 | ✅ 补图能解决 | 报缺口 + 请求重截 |
| **跨图断裂** | 用户发了 2 张以上，句子横跨两图 | ✅ 用户手上就有 | 直接合并，标断点 |
| **原文本身是节选** | 真题常从文章中间取一段，首句天然不完整 | ❌ 补图无用 | 标 `[原文节选]`，照讲可见部分，**不要请求补图** |
| **OCR 漏字 / 串行** | 语法突然不通、分栏文字左右混在一起、图注混入正文 | ⚠️ 换图或改文本 | 标 `[?]`，请求清晰图或直接发文本 |

**「截图切断」和「原文节选」必须分开**，这是最容易出错的地方：对节选文章喊"请补上一张图"，用户根本补不出来，只会困惑。

判别方法：看首句是否**语法上咬得住前文**。真题节选的首句通常语义完整（只是不知道前文背景），而截图切断的首句往往悬空——以 `and / but / which` 开头，或缺主语。

---

## 二、完整性检查四项（转写后立刻做，不要等到讲的时候）

### 第 1 项｜首句

| 信号 | 判定 |
|---|---|
| 首词小写 | 前文被切 |
| 以 `And / But / Or / Which / That / Because / So / Then / However` 开头 | 高度可疑，前文被切 |
| 直接以动词开头，无主语 | 前文被切 |
| 出现 `this / these / such / the former / the latter` 但文中无先行词 | 前面缺内容 |
| 首句语义完整，只是不知道背景 | 原文节选，非截图问题 |

### 第 2 项｜末句

| 信号 | 判定 |
|---|---|
| 没有终止标点（`. ? !`）收尾 | 被切 |
| 止于冠词 / 介词 / 连词（`the / a / of / in / to / and / that / than`） | 被切 |
| 止于及物动词但后面没有宾语 | 被切 |
| 止于形容词比较级 `more / less` | 被切 |

### 第 3 项｜内部断点

- 分栏排版：左右两栏文字被 OCR 串成一行 → 标 `〔串栏，需重截〕`
- 图注 / 页码 / 页眉混入：一律剔除，并在存疑处说明"已剔除图注 X 处"
- 跨图断点：在断点位置插 `〔图1/图2 断点〕`，判断落在句间还是句中

### 第 4 项｜成分完整度（决定判哪一档）

对可疑句子跑一遍五大成分清单：

```
主语 ？—— 有没有
谓语 ？—— 有没有（注意：非谓语不算）
宾语 / 表语 ？—— 及物动词后面有没有
```

- 三个都在 → A 档，正常讲
- 缺修饰（句首状语、句尾从句、插入语）但主干在 → B 档，讲，加边界标注
- 缺主语 / 谓语 / 主要宾语 → C 档，不译，进待补清单

## 三、三档的写法（照抄，不要临时发挥）

### A 档｜完整

正常四段式，不做任何标注。

### B 档｜残缺但主体可读

四段式照做，只改三处：

1. ① 原文两端加标记：`…[截断] which suggests that the decline in` 或 `The data show that …[截断]`
2. ② 译文用边界符号收口：`……〔后文截断〕` 或开头 `〔前文截断〕……`
3. 跳过 ⑦ 回译练习（残句无法练）

**正例**

> 原文：`…[截断] which suggests that the decline in`
> 译文：〔前文截断〕……这表明……〔后文截断〕

**反例（禁止）**

> 译文：……这表明下降的原因是人们不再重视这件事。

反例错在：`in` 后面缺了宾语，模型自己补了一个"人们不再重视"——这是编造，学习者会把它当成原文意思背下来。

### C 档｜残缺到不成立

不用四段式，改用固定五栏：

```
#### 句 3.5［截断，暂不译］

**可见部分**：`… which suggests that the decline in`
**缺什么**：缺 `in` 之后的宾语中心词；全句谓语尚未出现
**预估作用**：（据上下文推测，非译文）这一句大概率在解释前面数据的含义
**怎么补**：重截 P3 最后两行，上下各留一行空白
```

**五栏的硬边界**：

- 「预估作用」一栏必须带"（据上下文推测，非译文）"字样，且**只写句子功能，不写句子内容**
- 可以写"这一句在解释数据"，不可以写"这一句说下降是因为经济不好"
- 「缺什么」要具体到词性和位置，不要写"句子不完整"

## 四、待补清单

出现过 B / C 档就建表，每新增一条就更新，**并且在每次输出的末尾重贴当前清单**（用户不一定记得往上翻）。

```
### 待补清单
| 编号 | 位置 | 缺什么 | 怎么补 |
|---|---|---|---|
| 1 | 句 1.1 之前 | 首句以 and 开头，缺前一句 | 补发上一段结尾截图 |
| 2 | 句 3.5 | 图底切断，缺 in 之后的宾语 | 重截 P3 最后两行 |
```

清单可以清空，但要显式写"待补清单已清空"，不要默默消失。

---

## 五、接续规则（收到新图时先做，别急着讲新内容）

```
收到新输入
   ↓
① 转写新内容
   ↓
② 比对：新内容开头能否接上清单里最后一个缺口？（看语法咬合 + 内容连贯）
   ↓
   能接上 ──→ 标题写「【补讲 句 3.5】」→ 完整四段式 → 更新清单 → 再讲新内容
   ↓
   接不上 ──→ 明确说"这张和上次的句 3.5 对不上，那处仍缺失" → 保留清单 → 讲新内容
   ↓
③ 新内容自己又产生缺口 → 追加进清单
```

**对话示例**

> 用户：（发图1，底部正好切断在 `which suggests that the decline in`）
>
> Agent：`完整性检查：句 3.5 被图片底边切断，缺 in 之后的宾语，已记入待补清单。这句我先不译，等你补图。下面先讲 P1–P2。`
> （讲完 P1–P2，末尾重贴待补清单）
>
> 用户：（发图2）
>
> Agent：`图2 开头正好接上句 3.5 的 in 后面，先补讲这一句。` →【补讲 句 3.5】完整四段式 → `待补清单已清空。` → 继续讲 P3。

**用户说"不用管，继续"**：尊重，不纠缠。但缺口仍记入清单，Step 5 结尾必须给完整性核对，不能当作讲完了。

---

## 六、完整性核对（Step 5 结尾必给）

```
本篇共 24 句，其中 2 句因截断未讲（待补清单编号 1、2），补图后我可以补讲。
其余 22 句已全部讲完。
```

只要 M > 0 就必须出现这一行。**不允许用"以上就是全文讲解"收尾后还留着没讲的句子。**

---

## 七、给学习者的截图建议（可直接复制回复他）

> 想彻底避免缺口，按这几条截：
> 1. 上下各多留**一行空白**，别贴着文字边缘剪
> 2. 不要切在句子中间——**按段落边界切**
> 3. 长文章分 2–3 张，每张 1–2 段，别一张塞 5 段（字号会太小，OCR 容易错）
> 4. 截图前把手机的"护眼模式/深色模式"关掉，识别率更高
> 5. 最稳的是**直接发 PDF 或复制文本**，完全没有识别环节

## 八、自检

转写完成后问自己四个问题：

1. 首句有主语和谓语吗？末句有句号吗？
2. 有没有哪句的语法成分对不上，我是不是自动脑补了一个词？
3. 我的译文中，有没有哪一处无法对应回原文的具体单词？
4. 待补清单有没有同步更新，并且贴在了这次输出的末尾？

第 3 题答"有"，就是编造了，立刻改成边界标注。
